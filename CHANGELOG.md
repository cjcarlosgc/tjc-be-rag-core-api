# CHANGELOG

Todos los cambios notables de la línea base SDD se registran aquí. El contenido vigente vive en `spec/`; este archivo no reemplaza la especificación.

## [Unreleased]

- **Cambio de contrato aprobado (SDD 1.2 → 1.3):** el alcance implementable V1 queda exclusivamente en TypeScript (`.ts/.tsx`), aunque académicamente se ubique en el ecosistema JavaScript/TypeScript. El baseline aislado queda sustituido por `GENERALIST_AGENT`, un agente contemporáneo con exploración controlada y trazable del mismo snapshot; HU19 compara esa estrategia contra la arquitectura RAG especializada. La validación final se orienta al área de desarrollo de una empresa real, sin trasladar al SDD datos académicos o administrativos. Se documenta la topología de dos backends y un frontend.
- SDD 1.3 incorpora puertas de decisión acotadas: `DEC-CHUNK-001` y `DEC-EMB-001` bloquean el retrieval definitivo; `text-embedding-3-small` continúa como default provisional y `voyage-code-4` como candidato, sin congelar dimensionalidad final; `DEC-EXP-002` bloquea HU19 hasta definir las herramientas/paridad del agente generalista. `DEC-RAG-001` (posible señal test-aware) y `DEC-MET-001` (mutation score/StrykerJS) quedan PENDING para investigación posterior al núcleo de Sprint 2 y no bloquean trabajo no relacionado. Se descartan la prohibición general por leakage y la ablación obligatoria semántico/estructural/híbrido.
- Se explicita en `002-project-version-indexing` el diseño realmente implementado: discovery filtrado, parsing ts-morph, chunk por declaración top-level con fallback `FILE`, inventario separado, embeddings batch, persistencia pgvector y responsabilidades de los servicios. No se modifica código ni se declara definitiva esa estrategia para retrieval.
- Se incorpora contexto operativo canónico y una puerta de decisiones por work item en el harness. El cambio separa los handoffs de tesis del contrato de software, evita bloqueos por pendientes no relacionados y documenta vacíos de completitud; no altera comportamiento funcional ni incorpora contenido académico.
- Se resuelve la decisión PENDING de package manager: `pnpm` (`spec/constitution/tech-stack.md`).
- Se implementa HU01 (`001-project-management`): scaffold NestJS + Prisma/PostgreSQL en `app/`, módulo `projects` (crear/consultar), envelope de error estándar, correlationId, config validada y health check.
- Se resuelve la decisión PENDING de mecanismo durable de jobs: cola DB-backed en PostgreSQL (`spec/constitution/architecture.md`, `spec/transversal/async-jobs/`).
- Se resolvió inicialmente la decisión PENDING de proveedor de Object Storage con un adaptador S3-compatible; esta decisión queda sustituida por el cambio SDD 1.2 descrito a continuación.
- Se implementan HU02, HU03, HU04, HU05 y HU07 (`002-project-version-indexing`): carga de ZIP con validación síncrona (formato/tamaño/compatibilidad), indexación asíncrona vía cola de jobs DB-backed (extracción segura, parsing ts-morph, chunking, embeddings OpenAI, persistencia en pgvector), y endpoints de progreso/resultados.
- **Cambio de contrato aprobado (SDD 1.0 → 1.1):** `TestTarget.targetType` pasa de `CLASS|METHOD` a `CLASS|METHOD|FUNCTION` para permitir funciones top-level como objetivos testables sin forzarlas a la forma `METHOD` sin clase (`004-rag-retrieval-context`). Reglas: CLASS usa `symbolName` sin `methodName`; METHOD usa `symbolName` (clase) + `methodName`; FUNCTION usa `symbolName` (función) sin `methodName`. Como consecuencia, el modo de generación puntual de `005-test-generation` se renombra de `METHOD` a `TARGET` (resuelve un `TestTarget` de tipo METHOD o FUNCTION indistintamente). Se ajusta también `003-test-inventory` para referenciar el mismo contrato.
- Se implementa HU06 (`003-test-inventory`): inventario de `TestTarget` (clases/métodos/funciones exportados), detección de framework Jest/Vitest sin inventar cuando es ambiguo, resolución heurística de pruebas existentes por convención de imports, y exposición vía `GET /project-versions/:id/results` (resumen) y `GET /project-versions/:id/test-inventory` (detalle).
- **Cambio de decisión aprobado (SDD 1.1 → 1.2):** el proveedor concreto de Object Storage pasa a ser Supabase Storage vía `@supabase/supabase-js`, encapsulado detrás de la abstracción interna `ObjectStorageService`. PostgreSQL + pgvector en Supabase permanece como almacén de datos de dominio, chunks, embeddings vectoriales y cola DB-backed de jobs (`spec/constitution/tech-stack.md`, `spec/constitution/architecture.md`, `spec/transversal/object-storage/`).
- Se implementa la migración de código del cambio SDD 1.2: se retira el adaptador S3-compatible (MinIO) y sus dependencias (`@aws-sdk/*`), se agrega `SupabaseObjectStorageAdapter` (`@supabase/supabase-js`) detrás de `ObjectStorageService` (clase abstracta, sirve como su propio token de inyección), con verificación/creación de bucket perezosa para no acoplar el arranque de la app a la disponibilidad de Supabase. Ver `harness/reports/object-storage-supabase-migration.md`.
- Fix: `ProjectVersionsService.startIndexing` marca la `ProjectVersion` como `FAILED` (en vez de dejarla huérfana en `PENDING`) si falla la subida del snapshot, `setSnapshot` o el encolado del job; evita que un `Project` quede bloqueado permanentemente con 409 `PROJECT_INDEXING_IN_PROGRESS` tras un fallo transitorio de storage/jobs.
