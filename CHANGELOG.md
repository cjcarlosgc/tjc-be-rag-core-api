- **Cambio de contrato aprobado (SDD 1.0 → 1.1):** `TestTarget.targetType` pasa de `CLASS|METHOD` a `CLASS|METHOD|FUNCTION` para permitir funciones top-level como objetivos testables sin forzarlas a la forma `METHOD` sin clase (`004-rag-retrieval-context`). Reglas: CLASS usa `symbolName` sin `methodName`; METHOD usa `symbolName` (clase) + `methodName`; FUNCTION usa `symbolName` (función) sin `methodName`. Como consecuencia, el modo de generación puntual de `005-test-generation` se renombra de `METHOD` a `TARGET` (resuelve un `TestTarget` de tipo METHOD o FUNCTION indistintamente). Se ajusta también `003-test-inventory` para referenciar el mismo contrato.
- Se implementa HU06 (`003-test-inventory`): inventario de `TestTarget` (clases/métodos/funciones exportados), detección de framework Jest/Vitest sin inventar cuando es ambiguo, resolución heurística de pruebas existentes por convención de imports, y exposición vía `GET /project-versions/:id/results` (resumen) y `GET /project-versions/:id/test-inventory` (detalle).
- **Cambio de decisión aprobado (SDD 1.1 → 1.2):** el proveedor concreto de Object Storage pasa a ser Supabase Storage vía `@supabase/supabase-js`, encapsulado detrás de la abstracción interna `ObjectStorageService`. PostgreSQL + pgvector en Supabase permanece como almacén de datos de dominio, chunks, embeddings vectoriales y cola DB-backed de jobs (`spec/constitution/tech-stack.md`, `spec/constitution/architecture.md`, `spec/transversal/object-storage/`).
- Se implementa la migración de código del cambio SDD 1.2: se retira el adaptador S3-compatible (MinIO) y sus dependencias (`@aws-sdk/*`), se agrega `SupabaseObjectStorageAdapter` (`@supabase/supabase-js`) detrás de `ObjectStorageService` (clase abstracta, sirve como su propio token de inyección), con verificación/creación de bucket perezosa para no acoplar el arranque de la app a la disponibilidad de Supabase. Ver `harness/reports/object-storage-supabase-migration.md`.
- Fix: `ProjectVersionsService.startIndexing` marca la `ProjectVersion` como `FAILED` (en vez de dejarla huérfana en `PENDING`) si falla la subida del snapshot, `setSnapshot` o el encolado del job; evita que un `Project` quede bloqueado permanentemente con 409 `PROJECT_INDEXING_IN_PROGRESS` tras un fallo transitorio de storage/jobs.
